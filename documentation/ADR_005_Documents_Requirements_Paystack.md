# ADR 005 — Programme document requirements and Paystack payments
Date: 2026-10-31
Status: Implemented in package; requires local verification and production review
Baseline: GitHub commit 8dd991f, branch master

## Decision
- Retain the current MySQL models and admissions route namespace.
- Add normalized per-programme document requirement overrides instead of hardcoding requirements into view templates.
- Four document types remain required for all applications. Secondary O'Level and optional/conditional documents are independent slots.
- No programme accreditation, JAMB applicability, official fee or academic approval is inferred; authorized staff must publish those values.
- Preserve private local disk storage, locked application state, and owner/staff authorization for preview/download.
- Scan uploads with ClamAV in production; unscanned documents are clearly identified in development and are not allowed for production submission.
- Payment attempts are recorded before redirect; Paystack secret keys stay in environment settings; only server-verified matching transactions can become paid.
- Verify callback and signed webhook transactions against Paystack's API; compare reference, email, amount and currency; retain payment records for audit.
- `stsams_application_fee_kobo` is per admission session. `null` means not configured, `0` is an explicit waiver, positive amounts require Paystack.
- Payment receipt and application acknowledgement are generated by STSAMS rather than uploaded by applicants.

## Operational caveats
- Paystack webhooks cannot reach `127.0.0.1`; use a secure publicly accessible HTTPS staging domain/tunnel for webhook testing.
- Paystack keys are not included; no transactions can start until configured.
- An antivirus deployment is mandatory before production release.
- Financial reconciliation, refund workflows, vulnerability assessment, data retention, and payment-dispute processes remain pre-production obligations.
- Existing legacy uploads retain their original document type but do not automatically fulfill new required slots.
